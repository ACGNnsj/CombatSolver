# 等价剪枝的已有机制与项目适用性（2026-09-29）

本轮是文献与源码审计，基于 `79f8ff73`，没有启用新剪枝或产生新性能数据。此前[实测报告](duplicate-choice-pruning-broad-20260929.md)的收益与限制仍有效。下面分别标明已有研究、项目事实和待验证的迁移建议。

## 1. 问题分类

这属于状态空间爆炸中的重复探索问题，但至少有三种不同的重复：

| 本项目情形 | 对应机制 | 当前覆盖与缺口 |
|---|---|---|
| 换一张语义相同的实体牌打出 | 对称性消除 / canonical operators | `ExpansionPlan` 已按可打出牌指纹保留代表，不仅针对打击；持久选牌另有实体补留 |
| A→B 与 B→A 达到等价的未来状态 | 偏序约简（POR）、stubborn sets、sleep sets | 已有终态转置合并，但它通常发生在模拟之后；通用模拟前交换性证明是另一件事 |
| 不同历史路径到达同一状态且一条成本不优 | 转置表与支配标签 | 已有准入/展开两张表和多维标签，不能再当作从零新增的优化 |

对称性改换实体身份；POR改换动作次序，两者并不相同。已有研究证明它们可在特定最优规划算法和安全剪枝条件下组合，不能把该结论直接移植成有界Beam的质量保证。[IJCAI 2015：Integrating Partial Order Reduction and Symmetry Elimination](https://www.ijcai.org/Proceedings/15/Papers/244.pdf)

同名、当前伤害相同、最终HP相同，均不足以建立以上关系。费用层失效、位置、引用、牌堆、历史、RNG、目标和终局偏好仍可能区分两个分支。

## 2. 最值得迁移：资源感知的偏序约简

普通读写冲突分析会把共用能量的所有动作连在一起，导致几乎不能剪枝。ICAPS 2018 的资源规划研究专门处理这个问题：加减型资源在一定条件下允许重排；只消耗资源与可生产资源需要不同分析，补满、容量与溢出也不能一概处理。[On Stubborn Sets and Planning with Resources](https://fai.cs.uni-saarland.de/hoffmann/papers/icaps18b.pdf)

**项目迁移建议，尚未证明：** 先描述一个保守的动作效果合同，覆盖前置条件、读取/写入字段、资源变化、Hook、牌堆位置、历史、RNG、身份引用与终局检查。未知效果视为可能依赖。固定费用且能量足够时，可以排除“仅共享能量”的假冲突；这并不排除其他冲突。

例如两张牌都是1费并不构成证据：打出后弃牌顺序可能不同，某次出牌可能触发计数奖励或击杀，费用还可能取决于前一动作。原生Hook、自动子出牌和选择链均应包含在合同中，不能只检查卡牌主效果。伤害/格挡的可交换加法也不能代替全状态检查。

最低局部要求是：两种次序均合法、执行后的未来相关状态等价、质量标签一致。还需证明这些局部规则在所采用的搜索约简算法中成立，而不是发现一次 `AB == BA` 就跨状态缓存“这两类牌永远可交换”。

适用方向不局限于重复牌：不同牌、牌与药水、多个独立目标都可能成为候选。但目标死亡、监听顺序、药水槽及随机目标会显著收紧条件，首版不同时开放这些范围。

## 3. 低开销依赖分析：atom-centric stubborn sets

stubborn sets选择一个满足必要动作、使能和干扰闭包条件的动作子集。SoCS 2020 的实现将重复的动作间分析改为围绕状态事实建立索引和工作队列；Fast Downward 已提供 `atom_centric_stubborn_sets`。论文也明确展示：即使算法更便宜，部分领域的剪枝开销仍会超过收益。[An Atom-Centric Perspective on Stubborn Sets](https://ai.dmi.unibas.ch/papers/roeger-et-al-socs2020.pdf)

**可迁移的工程机制：** 使用保守依赖类别和紧凑位图，按类别维护动作索引，避免每个节点对全部动作逐对反射和试跑。例如资源、牌堆顺序、抽牌、目标阵容、出牌历史及随机流可以分别记账；类别相交只代表“需要进一步检查”，类别不相交也只有在描述完整时才有证明价值。加法资源的特殊规则另行核对。

本项目的原版镜像、动态Hook和第三方登记不是论文的有限域规划输入，不能直接把完整求解器替换成PDDL，也不能把现有 `Pure` 标签当作独立性合同。`BuildCandidate` 的pure判断来自事后历史分类，并未给出完整读集证明。

## 4. 优先于全状态规范化：局部动作代表

IJCAI 2015还研究了在保持当前状态不变的结构对称下，只保留每类动作的规范代表。它提示一个更窄的推广路线：能证明候选动作的对称性时，尽早减少后继生成，无须先对整个战斗对象图做规范化。[同一论文，第4节](https://www.ijcai.org/Proceedings/15/Papers/244.pdf)

项目已有出牌指纹去重；真正新增的工作是审核尚未覆盖的动作类型和持久选择，而不是重复加一个HashSet。每条新规则要给出身份置换如何覆盖 `Original`、`CloneOf`、附着模型、挂起选择和部署令牌。规范状态只用于搜索时，也须能够还原为实际可部署实体。

不建议直接排序所有牌堆或合并同名怪物。`PileOrderInvariantMask` 已是默认0的研究开关；它不提供位置不敏感证明。即便后续洗牌有稳定排序，也需单独核对相同排序键的原顺序及所有其他位置/引用消费者。

## 5. 应借鉴的成本控制：limited pruning

Fast Downward 的 `limited_pruning` 在指定数量的展开后检查累计剪枝比例，低于阈值就关闭包裹的剪枝器。官方文档还指出，高详细度的逐次计时本身可能产生显著开销。[官方文档](https://www.fast-downward.org/latest/documentation/search/PruningMethod/)；[实际实现](https://raw.githubusercontent.com/aibasel/downward/main/src/search/pruning/limited_pruning.cc)

**项目迁移建议：** 新的昂贵判定应有独立开关与有限试用窗口，记录检查次数、证书命中、避免的物理Fork和检查成本；推广前至少满足“判定成本低于避免的模拟成本”。阈值从本项目数据决定，不照抄默认值。采用固定工作计数和确定性决策点，计时离线取样，避免根据线程时序改变每次搜索行为。

需要区分两种关闭：关闭构造复用只是多花计算；关闭剪枝会增加候选，在固定Beam/节点预算下可能改变结果。因此不能声称“自动关闭必然保持原路线”，也不能借这个包装器给未经证明的剪枝兜底。若后来采用有状态的sleep set，还要保证关闭时没有遗留未完成的探索义务。

## 6. 不宜直接套用：DPOR / sleep sets

DPOR动态记录执行之间的依赖，据此安排必须补探索的次序，而不是枚举所有交错。它可启发离线的重复轨迹研究；原论文机制还包括回溯安排，绝不等于“日志里没看到冲突就永久剪掉”。[Flanagan与Godefroid，POPL 2005](https://www.nokia.com/bell-labs/publications-and-media/publications/dynamic-partial-order-reduction-for-model-checking-software/)

我们的历史记录不足以充当完整读写轨迹：读到但没有改变的值、条件分支和动态Hook仍可能形成依赖。先观测AB/BA完整结果差异可以找反例和估计机会，不能单凭有限样本形成通用安全证明。

另一障碍是搜索界限。BPOR研究表明，直接将普通DPOR与抢占界限组合可能遗漏界限内的执行，需要处理由界限引入的新依赖。该论文的界限不是Beam；这里借鉴的是“约简与边界必须联合证明”，而非声称它已经解决了本项目。[Bounded Partial-Order Reduction，OOPSLA 2013](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/bpor-oopsla-2013.pdf)

**针对本项目的推论：** 不能因为理论上A→B等价于B→A，就剪掉B→A，并假设A分支以后一定会执行。A可能已经被Beam、动作配额、预算或保路政策淘汰。一个可研究的保守试验是仅在同一确定性提交范围内已有可消费、成本不劣的等价结果时复用；但还须处理路线元数据和现有转置旁路，不能只持有一个“见过该状态”的标志。若需要永久保存更多代表，内存成本也必须计入。

## 7. 源码接入点与下一轮实验顺序

| 位置 | 当前职责 | 研究用途 |
|---|---|---|
| `src/Search/CombatBeamSolver.ExpansionPlan.cs` | 合法出牌枚举与指纹去重 | 经证明的新动作代表应在昂贵Fork之前判断 |
| `src/Search/CardChoiceSupport.cs` | 组合与实体代表、令牌构造 | 局部对称规则；保持实体映射及选择顺序 |
| `src/Search/CombatBeamSolver.Expansion.Candidates.cs` | 候选分类、准入与展开转置 | 定位重复何时被发现；区分已经付出的模拟成本 |
| `src/Search/CombatBeamSolver.Transpositions.cs` | 用药、卖血、战损、动作数、评分标签 | 新等价关系必须保留的成本比较 |
| `src/Search/CombatBeamSolver.StateEvaluation.cs` | 状态/牌/有序牌堆指纹 | 两条路径差异归因，不能单靠放宽哈希制造命中 |
| `src/Search/CombatBeamSolver.BeamRetentionPolicy.OrderedMutation.cs` | 非交换变异路径的保留 | 不能将其有限模式检测反推为其余动作全部可交换 |
| `src/Search/CombatBeamSolver.Models.cs` | 单次搜索的转置与缓存所有权 | 新诊断/依赖索引若落地，应有界且不跨搜索持有模型 |

建议按下列顺序推进；这是设计结论，尚未实施：

1. **先量收益上限。** 在既有19根上离线分辨：重复实体、动作次序、状态相同但标签不同、牌堆顺序不同。记录发生在Fork前还是后、重复模拟成本和规则检查成本。使用已经自然产生的轨迹优先；额外双跑仅限研究样本。
2. **首个生产候选选局部动作对称。** 仅对一类此前未覆盖、身份引用可完整核对的候选建立证明。若机会主要来自顺序，则先建立窄的资源/效果合同，不能用牌名白名单代替Hook与分支条件。
3. **独立检查搜索保留条件。** 小状态穷举完整可达结果和质量集合；此外构造Beam淘汰代表、零费循环、资源不足/生成、死亡触发、RNG、费用到期、不同位置与CloneOf等反例。
4. **用固定预算检验质量和净收益。** 原有整场五角色、首领离线根、DOP1/2，以及更多命中规则的场景；比较实际战损、用药、成长与续用，不要求新剪枝保持转移数不变，也不因终局HP相同就宣布正确。诊断计时和生产计时分离。
5. **无净收益则关闭或撤回。** 先用固定配置证明收益，再决定是否需要自适应包装。全图规范化、通用DPOR和跨回合宏动作暂不作为低成本首选。

判断：该方向有成熟理论与实现可借鉴。最有价值的推进是把“检查局部等价”变成“带完整条件、可低成本判断、能在Fork前生效的规则”，并联合处理Beam保留；论文中的最优性保证不能替代这一步。
